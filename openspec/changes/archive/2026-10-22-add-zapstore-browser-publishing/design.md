# Design

The release workflow verifies the APK using Android build tools and emits a JSON descriptor containing its package, version, version code, digest, size, certificate fingerprint, SDK levels and supported platforms. The docs metadata generator accepts a descriptor only when it matches the selected GitHub APK and the established signing certificate, verifies the downloaded bytes, and deploys a hash-addressed APK with a same-origin descriptor.

The browser shows the candidate before any signing request. An explicit publish action checks the NIP-07 identity against the existing project publisher, queries the existing beta release, verifies the same-origin APK digest, and uploads it to the Zapstore CDN with a signed Blossom authorisation when needed. It then signs and publishes a NIP-82 software asset followed by its referencing beta release. Signed payloads must match the requested fields and event hashes. The relay validates event signatures; only matching positive acknowledgements followed by release readback count as success. Existing app metadata and certificate linking are preserved.

All network operations have bounded timeouts. Rejected signatures, incorrect identities, unavailable candidates, mismatching hashes, upload failures and relay rejections remain actionable failures. Retrying after partial publication reuses the uploaded blob; an already published candidate reports that no update is needed. No private keys or GitHub credentials are requested or stored by the page.

The existing docs deployment listens for completion of the Android preview workflow on main in this repository. Client, server and e2e jobs are skipped for that event. Docs refresh after both successful and failed release runs, so a published APK still becomes a browser candidate when the optional Zapstore signer fails. The generator consumes verified GitHub release assets, and existing Pages deployment serialisation and coverage restoration remain in effect. No additional workflow permissions are introduced.

Browser sources are strict TypeScript in docs/src. The repository typecheck includes tsconfig.docs.json. A dependency-free Node 24 build strips types and rewrites relative module extensions to emit the browser modules during deployment; generated JavaScript and prepared APKs are excluded from version control. Browser tests exercise the generated modules.
